# 审计/复核剧本（audit：只读过程的终点纪律）

> 适用：接入审计、发布实录审查、接入复核、安全复查。**审计是只读过程：报告即终点。**

## 身份与边界

- 开工第一行输出身份声明（铁律 0）：`本次系统=<X>（依据：用户指定/用户确认）`
- 回执第一行必须含：`本次系统=<X> · 身份依据=用户消息指定/用户确认`
- 审计全程**只读**：不提交、不改配置、不 apply、不发版；发现缺口 → 写进回执待办，等用户指令

## 审计方法（实测优先）

回执结论必须有独立实测支撑，禁止照抄被审计方的声称：

| 声称类型 | 实测方式 |
|---|---|
| 自验通过（doctor/tests） | 本地复跑 |
| precheck 差异判定 | 复跑 precheck，逐文件核对方向（体积/md5/mtime + 内容超集） |
| bind mount 安全 | ssh 实测 `docker inspect` 挂载 + 目录结构 |
| 健康状态 | 实际探活（服务器本机视角，本机 curl 不算） |
| git 提交/产物 | `git show --stat` 核对范围 + `git status` 查残留 |
| 共享脚本改动 | git diff 归因（谁改的、为何改、是否声明） |

## 回执五段结构

① 字段清单 ② bind mount 结论 ③ 自验结果 ④ 差异归属判定 ⑤ 遗留待办。

## 常见误配信号（发现即写回执并报用户）

- 回执声称"已提交"但 `git status` 有该系统残留文件（两次实录）
- 共享脚本改动未在回执声明（doctor 放宽 / rsync exclude 混入他人提交）
- 身份依据是"历史记忆推断"而非用户指定（project-b 误配实录）
