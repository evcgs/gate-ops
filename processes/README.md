# 过程剧本注册表（Process Registry，v3.2.0 起；publish 为 v3.3.0 新增）

> 借鉴 spec-kit 的 process presets / extensions 思路：**过程本身是可组合的构建块**。
> 发版（release）是 core 过程；其余为扩展过程（extensions），各自声明入口条件、闸门、产物与终点。
> 任何过程开工前先过 SKILL.md **铁律 0（身份锚定）**：目标系统只能来自用户指定。

| 剧本 | 触发场景 | 终点（产出物） | 与其他过程的衔接 |
|---|---|---|---|
| `release.md`（core） | 用户要求发版/上线 | 验收通过 + 台账行 + 记忆写入 | hotfix 的前向修复走本剧本；data-change 不属于发版 |
| `rollback.md` | 真故障回滚（不受计划闸门限制） | 恢复 + 台账行 | 铁律 6 甄别后触发；可与 release 串联（回滚→修复→重发） |
| `onboarding.md` | 新系统接入 / 已接入系统复核 | 档案 + 标记 + 台账接入行 + 审计回执 | 复核≠发版；接入产出不自动进入 release |
| `data-change.md` | 数据库内容变更 / 批量生成 / 数据修复 | `gateo_data_*` 备份 + 台账 `data:` 行 | 不走 gateo-plan 闸门；写生产前仍须用户确认 |
| `audit.md` | 审计回执 / 复核报告 | 回执（第一行身份声明） | 审计是**只读**过程：报告即终点，不得自动转入 release/onboarding |
| `hotfix.md` | 线上故障 / 业务 bug | 根因结论 + 范围化修复 + 验证留痕 | 紧急回滚先走 rollback.md；前向修复走 release.md |
| `publish.md` | 对外发布：开源 GitHub / 官网 / 公众号 / 交付物脱敏 | 发布后独立复审 0 命中 + 发布台账行 | 对外发布=一次发版；脱敏映射表是可审计产物；发布≠宣传（宣传是新任务） |

## 入口解耦铁律（independent entry points）

- 每个过程有自己的**终点**；过程产出到下一个过程的转化**必须由用户指令发起**。
- 例：审计回执 ≠ 自动进入发版；接入完成 ≠ 自动发版；回滚成功 ≠ 自动修复。
- agent 不得以"顺手做完了"为由跨越过程边界——跨过程 = 新任务 = 需要用户指令。
