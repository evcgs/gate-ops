# 浏览器端到端验收（browser E2E）· 能力前置检查与操作规程

> 2026-11-03 用户裁定：发版完成后必须做浏览器端到端测试并截图留证；
> 前置检查当前 agent 是否具备浏览器操作能力，不具备则提示安装——以此闭环。

## E2E_MODE · 档案级配置（接入时确认，随时可调）

E2E 行为是**项目固有属性**，登记在项目档案 `profiles/<项目>.sh`（与 DEPLOY_MODE 同款思路），
**新项目接入时必须与用户确认档位**；之后随时可改档案字段调整，改完即生效，无需改脚本：

| 档位 | 行为 |
|---|---|
| `auto`（推荐缺省） | **前端发版必做 E2E**；**后端发版影响页面行为才做**（如接口修复反映到 UI → 做；纯接口新增无 UI 变化 → 文件级验收） |
| `always` | 所有发版都做浏览器 E2E |
| `off` | 关闭 E2E（文件级验收放行）；台账验收列必须如实记 **"部分验证（无浏览器 E2E）"** |

运行时临时覆盖：环境变量 `E2E_MODE=off`（优先级高于档案，单次发版有效）。

## 为什么需要

文件级验收（chunk 哈希一致、样式类包含）≠ 用户看到的页面正确。发版完成的定义是
"用户端到端可用"，浏览器实测 + 截图是验收闭环的硬环节，不是可选项。

## 第 0 步 · 浏览器能力前置检查（每次浏览器验收前必做）

按当前宿主 agent 自检：

| 宿主 | 自检方式 | 具备的标志 | 缺失时的安装路径（需用户确认后执行） |
|---|---|---|---|
| **WorkBuddy** | 尝试调用内置浏览器工具（开页面/截图），或确认 `workbuddy-browser-use` Skill 可用 | 能打开目标 URL 并截图 | 提示用户启用浏览器使用能力（内置 IAB 或浏览器扩展） |
| **Claude Code** | 检查 `claude mcp list` 是否有 playwright（或等价 browser MCP）；或直接试调其工具 | 能打开目标 URL 并截图 | `claude mcp add playwright -- npx @playwright/mcp@latest` |
| **Codex** | 检查 MCP 配置（`~/.codex/config.toml`）中的 browser/playwright server | 能打开目标 URL 并截图 | 配置 playwright MCP server |

**判定规则**：
- 能力具备 → 直接进入 E2E 流程
- 能力缺失 → **不得静默跳过、不得标 ✅**。如实报告用户"浏览器 E2E 无法执行"，二选一：
  1. 用户授权安装浏览器能力 → 装好后补做 E2E 验收
  2. 用户明确接受文件级验收放行 → 台账验收列如实记 **"部分验证（无浏览器 E2E）"** + 原因

## E2E 最小流程（前端发版必做；后端发版涉及页面行为的同样走）

1. **打开目标 URL**（确认闸门里的发版目标；Basic Auth 站点先备好凭据）
2. **验证本次变更点**：元素存在/文案/布局/交互——逐条对应确认闸门确认过的变更清单
3. **截图留证**：整页截图保存到 **`<技能目录>/evidence/<项目>/gateo-<发版目录>/gateo-e2e-<描述>.png`**
   （与 gateo-deploy-output.txt、gateo-acceptance-report.md 同目录，一次发版一套证据；路径写入验收报告与台账"证据"列）
4. **强刷复验**（Cmd/Ctrl+Shift+R 或清缓存）：防"页面仍加载旧 chunk"——与 05-acceptance
   的前端 SPA 最低验收标准（index.html chunk 核对）配合，构成"引用正确 + 渲染正确"双证明
5. 涉及登录态/角色差异的变更（如普通用户端 vs 管理端），用对应角色账号各验一次

## Agent 检查点

- [ ] 浏览器能力已前置检查（缺失时按判定规则处置，未静默跳过）
- [ ] 变更点逐条在真实页面验证，截图已保存且路径记入台账
- [ ] 强刷后页面实际加载的是本次构建产物
- [ ] 验收列如实标注：通过 / 部分验证（附原因）/ 回滚
