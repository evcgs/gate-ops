# 发版生命周期总览（Lifecycle Overview）

> 面向 agent。执行任何发版前先读本页；各阶段细节按需深读对应文档。

## 状态机

```
                    ┌────────────── 任何阶段失败 ──────────────┐
                    ▼                                          │
preflight → plan → approval → backup → apply → readiness → acceptance ──┤        ▼
 (预检)    (备份)    (发布)    (探活)   (验收闭环)    │    rollback（回滚）
                    │                                │        │
                    │      全部通过 ◄────────────────┘        │
                    ▼                                         ▼
                 ledger（台账）──────────────► memory（记忆同步）
                                                    │
                                              ✅ 发版完成（done）
```

**顺序铁律**：
1. 任何阶段不得跳过 `backup`（无备份不发版）
2. `health` 失败 = 发版失败 → `rollback`
3. `acceptance` 未闭环（通过或回滚完成）→ 禁止进入 `memory`，禁止宣称"发版完成"
4. `rollback` 本身也是一次发版事件：完成后同样走 `ledger → memory`

## 阶段产物与日志总表（每阶段完成即核对）

每个阶段完成时都有**产物**，产物去向分三级：**T1=台账**（`records/<项目>.md` 行 + `records/_index.md` 总目录）、**T2=宿主会话日志**（发版整体一条）、**T3=证据中心**（`evidence/<项目>/gateo-<发版目录>/`：脚本输出留档 + 验收报告 + E2E 截图，每次发版一个目录）。"产物只在脚本 stdout 里"不算完成——必须落到对应位置。

| # | 阶段 | 完成产物 | 产物落盘位置 | 完成即记录的动作 |
|---|---|---|---|---|
| 1 | preflight | 通过/阻塞结论 + 差异清单 | 会话日志（阻塞时完整粘贴差异）；差异清单同时是 release 确认闸门"覆盖资产"的输入 | 阻塞 → 立即报用户 |
| 2 | backup | 备份文件名（回滚基准） | **T1 台账"备份文件"列** + 会话日志 | 记下文件名，丢失=无法回滚 |
| 3 | release | 部署完成输出 + 远端验证 + 发布内容摘要 | 会话日志；脚本结尾自动打印台账行（待验收态） | 保留脚本完整 stdout |
| 4 | health | 探活输出（健康检查结果原文） | **T1 台账"健康检查"列** + 会话日志 | 失败 → 立即回滚分支 |
| 5 | acceptance | 验收报告（表格）+ 浏览器 E2E 截图 | **T1 台账"验收"列** + **T3 evidence/<项目>/gateo-<发版目录>/**（gateo-acceptance-report.md + e2e-*.png） | 通过/部分验证/回滚/带瑕疵放行四选一 |
| 6 | rollback | 恢复结果 + 复验（最小验收） | 台账新一行（结果=回滚）+ 会话日志 | 回滚本身也是发版事件 |
| 7 | ledger | 台账行（git 提交） | **T1 `records/<项目>.md` + git commit** | 脚本已打印行，补三列即可 |
| 8 | memory | 三层记忆同步记录 | 台账（真源）+ 宿主会话日志 + 项目长期记忆/功能标记 | acceptance 闭环后才允许 |

**检查方式**：任何时刻被问"这次发版走到哪了"，agent 必须能从落盘记录回答——当前阶段、各阶段产物在哪、最近回滚点是哪个文件。答不出 = 流程有欠账。

## 关键环节确认闸门（用户确认提醒）

以下环节 agent 必须**先向用户发出确认提醒并等明确同意**，不得以"用户已下过指令"为由跳过（指令是意图，确认是范围）：

| 环节 | 确认内容 | 例外 |
|---|---|---|
| 发版执行前（release 第 0 步） | 目标 + **将覆盖的云端资产**（preflight 差异清单）+ 备份文件名 + 模式 | 无 |
| 跳过检查发版（FORCE=1） | 差异清单全量报告 + 跳过风险 | 无 |
| 验收写生产库数据前 | 改哪张表/哪个接口、before 值怎么留、清理方式 | 只读（GET/SELECT）用例免 |
| 回滚执行前 | 恢复哪个备份、影响范围 | **health 失败的自动回滚豁免**（铁律 6 已授权，紧急不设闸门） |

模板见 `03-release.md` 第 0 步。**无低风险豁免（2026-11-03 用户裁定）**：纯前端/样式类/小改动发版同样走确认闸门。

## 浏览器端到端验收（E2E_MODE 档案配置）

验收含浏览器 E2E 实测环节，行为由项目档案 `E2E_MODE` 控制（接入时与用户确认，随时改档案调整）：
`auto`（前端必做/后端影响页面才做，推荐缺省）/ `always` / `off`（台账如实记"部分验证"）。
能力前置检查、三端安装路径、截图留证规程见 `references/browser-e2e.md`。

## 分层阅读规则（渐进披露）

- **第 1 层**：`SKILL.md` —— agent 默认只读这个即可执行例行发版
- **第 2 层**：`lifecycle/*.md` —— 遇到对应阶段或异常情况时深读
- **第 3 层**：`plans/<项目>/` —— 仅大版本/高风险发版时，先产出 `<版本>-release-plan.md` 经用户确认再执行

## 文档结构约定

每篇生命周期文档统一六段：**目标 / 前置条件 / 操作手册 / 失败处置 / 输出物 / Agent 检查点**。文档只写"行为契约"，不复制脚本参数细节——脚本 `--help` 与脚本头注释是参数的唯一权威来源。
