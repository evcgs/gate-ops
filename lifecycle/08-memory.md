# Phase 8 · memory（记忆同步）

## 目标

把本次发版事件的记忆写入各层记忆体系，使**任何 agent 在任何未来会话**无需重新摸索即可知道：发过什么、结果如何、回滚点是谁、有什么教训。

## 前置条件（硬闸门）

- **acceptance 已闭环**（通过 / 回滚完成 / 带瑕疵放行）
- ledger 已写入并 git 提交

## 操作手册（三层，缺一不可）

**第 1 层 · 跨 agent 台账**（`records/<项目>.md`）：已在 ledger 阶段完成，此处核对。

**第 2 层 · 宿主 agent 会话日志**（append-only，按宿主落点）：
- WorkBuddy：`{workspace}/.workbuddy/memory/YYYY-MM-DD.md` 追加
- Claude Code：项目 `CLAUDE.md` 的"部署记录"小节
- Codex：项目 `AGENTS.md` 的"部署记录"小节

格式：`[HH:MM] 项目=<名> 目标=<...> 结果=<成功|回滚> 验收=<n/n> 备份=<文件名> 异常=<无|简述>`

**第 3 层 · 项目长期记忆**（存在长期事实区时更新）：
- 最近回滚点文件名
- 新核心功能上线 → 把标记追加进 `scripts/feature-markers.txt`（或档案 `MARKERS_FILE`），防止下次发版丢功能
- 本次踩的坑若具有复用价值（如某依赖服务的坑），写入项目记忆"运维教训"区

## 失败处置

- 会话日志目录不存在 → 创建后写入（WorkBuddy：`mkdir -p {workspace}/.workbuddy/memory`）
- git 提交失败 → 排查仓库状态（是否有未暂存冲突），修好后补提交；台账必须进 git，否则三端不同步

## 输出物

- 三层记录的完成确认

## Agent 检查点

- [ ] 验收未闭环就写 memory = 违反闸门，禁止
- [ ] 三层都写了才可对用户报"发版完成（含记忆同步）"
- [ ] 新功能标记这一步最易漏——每次都要自查："这次上线的东西，需要成为预检标记吗？"
