# Phase 1 · preflight（发版预检）

## 目标

在动任何线上东西之前，证明两件事：①本地代码不会覆盖云端更新的代码；②本地构建产物不会丢掉云端已有功能。**preflight 是整条生命周期的安全闸门。**

## 前置条件

- SSH 可连通目标服务器（用只读命令验证即可）
- backend 模式：本地 `app/` 目录存在；frontend 模式：本地 `dist/` 已构建且非空

## 操作手册

```bash
# backend：rsync 校验和干跑，列出"云端有但本地没有/不同"的文件
bash scripts/precheck-deploy.sh backend <本地app目录>

# frontend：功能标记检查（云端已有标记，本地构建产物必须包含）
bash scripts/precheck-deploy.sh frontend <本地dist目录> <云端assets目录>
```

- 功能标记清单：`scripts/feature-markers.txt`（或档案 `MARKERS_FILE`）。**云端新上核心功能后必须追加标记**，否则下次发版预检保护不到它。

### 期望差异清单（例行发版免 FORCE 的正道）

例行发版的差异 = 本次待发文件本身，属正常。确认闸门（03-release 第 0 步）与用户确认期望清单后，用
`DEPLOY_EXPECT_DIFFS="文件1,文件2"`（相对 app 根，逗号分隔）传入发版命令，预检校验
**实际差异 ⊆ 期望清单** 即放行；出现**清单外**差异仍阻塞（可能是云端领先/本地未知改动）。
`FORCE=1` 只留给用户明确授权跳过全部检查的异常场景。

### 多机滚动预检（DEPLOY_TARGETS）

档案/环境设了 `DEPLOY_TARGETS`（空格分隔多台目标）时，backend 预检自动**逐台**执行 rsync 干跑，任一台出现清单外差异即整体阻塞——集群发版要求所有机器的基线一致，不允许"部分机器可覆盖、部分会被覆盖坏代码"。

## 失败处置

| 情形 | 处置 |
|---|---|
| 有差异清单（退出码 1） | **先判断差异方向（口诀：本地多=待发版正常；云端多=先同步 云端→本地）**。①本地领先：差异是已知未发版的本地工作 → 确认闸门确认清单后用 `DEPLOY_EXPECT_DIFFS` 正常发版（免 FORCE）；②云端领先：云端存在未知的改动（热修/他人部署）→ 事故信号，先做 云端→本地 同步再评估。判断依据：git diff/会话记录/改动时间（tar 发版会带本地 mtime 上云，云端 mtime 不构成热修证据） |
| 期望清单模式下列出清单外差异（退出码 1） | 清单外文件逐条判断归属：属本次待发 → 加入 `DEPLOY_EXPECT_DIFFS` 并告知用户；属云端领先 → 先同步 云端→本地 |
| SSH/rsync 失败（退出码 1，报"检查本身失败"） | **禁止用 FORCE 绕过**。先修网络/SSH 连通性。查不了 ≠ 查过了没差异 |
| 退出码 2 | 参数错误，修正调用参数 |

### 归属判定的标准手法（2026-11-04 project-b 实录沉淀）

差异归属拿不准时，按此流程判定并**留痕**：

1. **抓云端现状**：`ssh <目标> "cat <云端文件>"`（或关键片段），与本地 `diff` 对比
2. **比对特征**：云端文件是"改动前旧版"→ 本地领先（待发，正常）；云端含本地没有的新逻辑/新文案 → 云端领先（热修信号，先同步 云端→本地）
3. **结论必须落盘**（判定不出现在任何记录里 = 等于没判）：
   - 更新档案"未决事项"注释（判定完成 → 改为已判定 + 日期 + 判据摘要）
   - 台账备注记一行（判据 + 结论）
4. **判定后才允许生成发版计划**；计划中 `DEPLOY_EXPECT_DIFFS` 用**差异清单原样路径**（相对 LOCAL_APP_DIR，不是 git 仓库根路径——两者常不同，从 precheck 输出直接复制）

### 多会话并行修改（常态，非事故）

多会话各领任务并行改本地源码是允许的（前提：源码已 git 管理，见 `references/config-schema.md`）。预检报出的差异逐条归属：本会话的 → 待发；**其他会话进行中的 → 不纳入本次 EXPECT_DIFFS**（发它 = 把半成品推上生产），等其完成 commit 后再发。

## 输出物

- 退出码 0：通过，可进 backup
- 退出码 1：阻塞（含差异清单或失败原因）
- 退出码 2：参数错误

## Agent 检查点

- [ ] 绝不允许把"检查不了"当成"检查通过"
- [ ] 差异清单逐条报给用户，未获明确授权绝不 FORCE
- [ ] frontend 预检前确认 dist 是本次新构建的（防止旧产物混检）
